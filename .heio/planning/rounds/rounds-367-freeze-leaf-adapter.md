#### Problem

The bet is try a host config at the leaves; pivot if portable components import the host. [[purpose-host-config]] already parks that proof on [[purpose-leaf-kit]]. #### Usage

Apps keep importing `h`, `render`, and the closed leaves from dragonflame-ui. They write composites with `h(view, …)` and `h(text, …)`, then `render(App, parent)`. They never import HostConfig, Host, `document`, Metal, or UIView. A portable screen is still function components over the six leaves. Host contact stays inside the adapter that `render` already uses. Pivot if a composite starts importing the host.

#### Shape

Public surface stays `h`, `render`, and the closed kit. No public HostConfig. No public Host. Private leaf adapter owns the host map: DOM tags, future UIView, future engine draw lists. Shared code is composites only. Depth: those few names hide host choice. First drain locks the existing `leaf-kit.host:config-at-leaves` promise. CHECK lives in `tests/leaf-kit/config-at-leaves.test.mjs`. Do not point that CHECK at `tests/host-config/` steal tests or at portable-program tests. Do not freeze compile-time platform, New Architecture steal, or portable import.

Splitting load, map-tags, then mount as public steps is temporal decomposition. A HostConfig.create that only forwards to `render` is a pass-through. Pointing CHECK at steal tests or portable-program tests fakes progress.
